# 士林區 AI 住宅房價估價網站｜2026 Q3 更新（10 月現值推估）

這是**可部署的互動估價網站**，不是只有圖表的研究報告。網站使用內政部不動產實價登錄主表 **114S1–114S4、115S1–115S3**（2025 Q1 至 2026 Q3）中的士林區住宅交易，訓練三個模型：Hedonic OLS、Random Forest (500 trees)、Gradient Boosting (300 trees)。網站已附重新訓練好的模型，不需要使用者在 Mac 安裝 Python。

## 2026 年 10 月的「現在估價」是什麼？

- 最後一筆合格**實際成交日期**：2026-08-14（不是 2026 Q3 結束，也不是 10 月）。
- 網站讓使用者選擇 2026-10 作為**估價基準月份**，但沒有 10 月已成交樣本。因此 10 月價格是**以最新可觀察 8 月的模型估價為基準，外推 2 個月**，絕不是實時已驗證的房價。
- 外推法：先用 Hedonic OLS（完整樣本）估計月時間係數 b，再限制 b 在每月 ±0.01 的對數變化；對三種模型在 8 月的估價同乘 `exp(b * 2)`。這屬研究情境推估；日期與警示會顯示在網站。
- 只允許估價到「今天所在月份」，而且距最後有成交資料的月份最多三個月。資料太久沒有更新時，網站會**拒絕自稱能估算當期房價**。

## 從 GitHub 變成公開網站（不用在電腦安裝 Python）

1. 解壓 ZIP，打開含 `app.py`、`render.yaml`、`requirements.txt`、`model/`、`static/` 的資料夾。
2. 建議使用**新的 GitHub Repository**（或在舊 Repository 直接覆蓋原始檔）。務必把**這些檔案直接放在 Repo 根目錄**，不要又包一層資料夾。若舊檔出現不同名稱，移除它們以免混淆。
3. 如果已綁定 Render，提交 Commit 後等待自動部署；若還沒，在 https://dashboard.render.com → New → Blueprint，連結 Repository，Render 讀取 `render.yaml`。
4. 等 Render 顯示 Live，進入它提供的 HTTPS 網址。網站應顯示「1,091 筆」、樣本最新月份「2026-08」與預設選取「2026-10」。
5. 可以開 `https://你的網址/api/status` 檢查 `records`、`latest_month` 和三個模型的 `cv`。如果仍是 760 筆，說明部署仍使用舊版。

**不要在 GitHub 上傳下載來源 ZIP、住戶門牌完整交易資料、管理密碼或私密金鑰**。本交付包的 `model/` 包含模型、道路平滑統計與摘要，不包含完整逐筆門牌。

## 模型訓練（僅供重做研究／伺服器）

可用 Python 執行 `python training.py --input-dir /path/to/官方ZIP資料夾`。來源資料夾可同時包含官方季度 ZIP，以及內部包了季度 ZIP 的綜合 DATA.zip。會以 `編號` 去除跨檔重複，按原研究定義依序清理資料；五折交叉驗證時，路段 target encoding 只使用訓練資料。上傳資料的管理頁為 `/admin`，須在 Render 設 `ADMIN_TOKEN`，且必須逐季上傳七季原檔才可重訓。**免費 Render 重新部署時，臨時上傳與重訓的模型有可能消失；因此建議在本地或研究環境訓練後把新的 `model/` 檔案提交 GitHub 作為正式版本。**

## 研究限制

- 模型只支援士林區四個指定生活圈內的道路、公寓／華廈／住宅大樓，不能外推北投區或全台。
- 坪數必須是**扣除車位面積後的建物登記坪數**；另計車位價（自行填或粗略用已拆分車位價格中位數）。
- **原始資料有「電梯」欄位，但篩選後其與建物型態完全重合，無法估計獨立的電梯溢價**，網站保留輸入但不會改變估價。屋況、裝修、景觀、法規變更、完整門牌經緯度也未單獨納入。
- 五折 CV 反映既有樣本的誤差，不保證單一物件，亦無法證明 2026 年 10 月外推精準度。
- 原始單價取對數建模，再取指數還原；ML 額外使用只從訓練折學到的平滑路段價格，和 OLS 的變數集合不完全相同。
- 同一季的登錄資料可能包含較早的成交，請一律以實際「交易年月日」判斷時間。

**僅供課堂研究展示，不可取代專業不動產鑑價或銀行授信擔保品評價。**
